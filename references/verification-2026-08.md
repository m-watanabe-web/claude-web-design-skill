# 検証ログ：禁止リストは効くのか（2026-08-19）

## 目的
「禁止リストを渡すとAI感が減る」という前提が、現行モデルで成立するかを確かめる。
成立しなければスキル化そのものを中止する、という条件で実施した。

検証対象は、AI生成デザインの特徴として一般に流通している主張
（紫系グラデーション、絵文字、多色使い、均一なカードグリッド、過剰なアニメーション）。

## 方法
- **条件A（対照）**：ブリーフのみを渡す。禁止リスト・design-spec は渡さない。
  **この会話の文脈を持たない白紙のサブエージェント**が生成（生成者の汚染を避けるため）。
- **条件B（実験）**：同じブリーフ ＋ `forbid.md` ＋ `design-spec.yaml`。
- **題材2種**：(a) 日本茶ブランドLP（中立な架空案件）、(c) エンジニアのポートフォリオLP。
- **評価**：主観を排し、HTML/CSSへの機械測定（`measure.py`）。
- **事前登録した合否基準**：Bで違反が残れば中止／Aが既にクリーンなら前提崩壊とみなす。

## 結果

| 指標 | A-a | B-a | A-c | B-c | 判定 |
|---|---|---|---|---|---|
| 紫系の色 | 0 | 0 | 0 | 0 | 差なし |
| 絵文字 | 0 | 0 | 0 | 0 | 差なし |
| 装飾グラデーション | 1 | 0 | 0 | 0 | ほぼ差なし |
| 色相数 | 5 | 3 | 2 | 2 | 片方のみ |
| border-radius | 6 | 0 | 6 | 0 | **差あり** |
| 均一カード羅列 | 3 | 0 | 2 | 0 | **差あり** |
| アニメーション | 0 | 0 | 3 | 0 | **差あり** |
| サイズ | 44KB | 6KB | 21KB | 5KB | **差あり** |

対照群が実際に選んだ配色：(a) 緑→金→橙のアースカラー、(c) 紺＋青。**紫は出現せず**。

## 結論
**部分的に前提崩壊。** 最も広く言われている「紫グラデ」「絵文字」は、
禁止しない条件でも出なかった＝**何も禁止していなかった**。
一方、構造的な癖（角丸カードの均一グリッド、無意味アニメ、冗長さ）は明確に残る。
→ 禁止リストの内容を半分入れ替えた上で継続する、と判断。

## 測定器に混入したバグ（2件・修正済み）
1. 絵文字判定に矢印 `→`(U+2192) を含めており、「絵文字2件」は全て誤検出だった。
2. グラデーション抽出の正規表現が `)}` で終わる記述を取り逃し、
   `linear-gradient(90deg,#8FA97A,#C9A24B,#B4642F)` を見落としていた。
→ 括弧の対応を数える方式に変更。**初回の測定結果は両方とも誤りだった。**
チェックリストを作れば品質が担保される、という発想自体への反証。

## この検証の限界
- **各条件 n=1**。角丸6件のような大きい差は偶然で説明しにくいが、色相数の差は誤差の範囲。
- **対照群も同じモデル**（サブエージェントはセッションのモデルを継承）。
  検証できたのは「Opus 5の癖」であって「AI一般の癖」ではない。
- **実写真のレバーは検証不能**（オフラインで本物の画像を用意できず、両条件とも実素材0）。
- **Step 1・2 のプロセス論は未検証**（一発生成では差が出ない性質）。
- **ツール比較（Gemini等）は未実施**。

## 第2ラウンド：UX観点（同日）

見た目しか測っていなかったため、UX指標を追加して測り直した。

| 指標 | A-c（対照） | B-c（見た目リストのみ） | **B2-c（ux.md＋forbid.md）** |
| --- | --- | --- | --- |
| コントラスト違反（実測） | 0 | **4**（最悪 2.71:1） | **0**（最悪 6.15:1） |
| `:focus` | あり | **なし** | あり |
| `prefers-reduced-motion` | あり | **なし** | あり |
| `<main>` | あり | **なし** | あり |
| 見出し階層 | 正常 | **h1→h3 飛び** | 正常 |
| 空リンク | 0 | **1** | 0 |
| メディアクエリ | 9 | **1** | 2 |
| 角丸 | 6 | 0 | 0 |
| 均一カード | 2 | 0 | 0 |
| サイズ | 21KB | 5KB | 6KB |

**結論：見た目の禁止リスト単独では、対照群よりUXが悪化する。**
「角丸を使うな」「アニメを入れるな」「短くしろ」と縛った結果、フォーカス表示と reduced-motion が削られた。
対照群は指示なしでそれらを実装していた。
両方（`ux.md` ＋ `forbid.md`）を適用した B2-c で、**UX全項目クリア＋見た目クリアを両立**できた。

茶の題材でも同じ結果。B2-a（両方適用）で全項目クリア。

| 指標 | A-a（対照） | B-a（見た目のみ） | **B2-a（UX＋見た目）** |
| --- | --- | --- | --- |
| コントラスト違反（実測） | **64** | **15**（最悪 4.34:1） | **0**（最悪 6.76:1） |
| `:focus` / `<main>` / 見出し階層 | なし / なし / 飛びなし | **なし / なし / 飛びあり** | あり / あり / 正常 |
| 空リンク | 0 | **1** | 0 |
| 角丸 / 均一カード | 6 / 3 | 0 / 0 | 0 / 0 |

**どの条件でもコントラスト違反は出る**（対照群64件、見た目リストのみ15件）。
リストの有無に関わらず、提出前の実測は必須。

### 測定器のバグ（累計5件）
3. 静的解析のコントラスト判定が、入れ子の背景を追えず誤検出・見逃しの両方を起こした
   → Chrome headless の実レンダリングに切り替え（`contrast.py`）
4. Chrome は `color-mix()` を `color(srgb ...)` 形式で返すため、`rgba()` だけを見ていた解析器が
   **該当要素を黙って検査対象外にしていた**（B系が「違反0件」に見えていた）

5. `transition` が設定されていると、テーマ切替時に色が遷移し切る前に測ってしまい
   **偽陽性**が出た（`a{transition:color .3s}` だけで 1.19:1 と誤判定）。
   → 測定前に `*{transition:none!important;animation:none!important}` を注入して解決。
   **このバグは、スキルを渡した第4ラウンドのエージェントが指摘して発覚した。**

**「違反0件」も「違反あり」も、まず測定器を疑う。** 5件中2件が偽陰性、1件が偽陽性だった。

## 第3ラウンド：作り込みの抑制は制約のせいか（同日）

第2ラウンドで「禁止リストは余計な装飾と一緒に野心も削る」と結論したが、**これは誤りだった**。

同じ制約（`ux.md` ＋ `forbid.md`）に「本文を厚く、必要なら図版も作る」の一文を足した条件を追加。

| 指標 | A 対照群 | B2 UX＋見た目 | **B3 ＋作り込みを明示** |
| --- | --- | --- | --- |
| 図版（SVG） | 9点 | 1点 | **7点** |
| 本文 | 3,662字 | 432字 | **1,335字** |
| サイズ | 44KB | 6KB | 14KB |
| コントラスト違反（明/暗） | 64 / 64 | 0 / 0 | **0 / 0** |
| UX全項目 | 4項目違反 | クリア | **クリア** |
| 見た目（角丸・均一カード） | 6 / 3 | 0 / 0 | **0 / 0** |

**結論：制約と作り込みは両立する。** 抑制していたのは制約ではなく、作り込みを求めなかったこと。
禁止リストは「やらないこと」しか書いていないため、単独では最小限の出力に落ちる。

### この追試の限界
- **B3は制約を熟知した状態での最善手**であり、対照実験ではない。
  「両立が可能」という存在証明であって、手順が毎回この品質を出す証明ではない。
- 対照群の水準（3,662字・9点）には届いていない（1,335字・7点）。
  残差が制約由来か労力由来かは分離できていない。

## 第4ラウンド：スキルを白紙のエージェントに渡す（同日）

第3ラウンドの B3 は**制約を熟知した状態での最善手**であり、対照実験ではなかった。
そこで、この会話の文脈を持たない白紙のエージェントに **`SKILL.md` / `ux.md` / `forbid.md` と
測定器だけを渡し**、ブリーフと「本文は厚く、必要なら図版も」の一文を添えて生成させた（= B3c）。
自己検査で違反ゼロになるまで直すことも指示に含めた。

### 題材1（日本茶LP）

| 指標 | A 対照群 | B2 UX＋見た目 | B3 手書き | **B3c スキルのみ渡す** |
| --- | --- | --- | --- | --- |
| 本文 | 3,662字 | 432字 | 1,329字 | **4,495字** |
| 図版（SVG / path） | 9 / 53 | 1 / 0 | 7 / 32 | **8 / 60** |
| サイズ | 44KB | 6KB | 14KB | 41KB |
| コントラスト違反（明/暗） | 64 / 64 | 0 / 0 | 0 / 0 | **0 / 0** |
| UX全項目・見た目 | 違反あり | クリア | クリア | **クリア** |

### 題材2（ポートフォリオLP）

| 指標 | A 対照群 | B2 UX＋見た目 | **B3c スキルのみ渡す** |
| --- | --- | --- | --- |
| 本文 | 1,915字 | 576字 | **3,656字** |
| 図版（SVG / path） | 0 / 0 | 0 / 0 | **6 / 59** |
| コントラスト違反（明/暗） | 0 / 0 | 0 / 0 | **0 / 0** |
| UX全項目・見た目 | 角丸6・カード2 | クリア | **クリア** |

### 結論

**スキル一式を渡すだけで、対照群を上回る作り込みと全項目クリアが両立した。**
両題材とも本文量が対照群を超え（4,495字 vs 3,662字 / 3,656字 vs 1,915字）、
題材2では対照群がゼロだった図版が6点入った。修正回数はいずれも1回。

第3ラウンドの手書き B3（1,329字）が最も痩せていた点は記録しておく。
**制約を知っている人間が書くより、制約をファイルとして渡した方が良い結果になった。**

### 限界
- 各条件 n=1。生成エージェントは親と同じモデル（Claude Opus 5）。
- 「作り込みを明示する一文」は指示に含めており、スキル本体には無い。
  → `forbid.md` に「単独では痩せる。何を作り込むか別途指示せよ」と明記して補った。

## クロスモデル検証（未実施）

「紫グラデも絵文字も現行モデルは出さない」という主張は **Claude Opus 5 でしか確かめていない**。
モデル固有の性質か現行世代に共通かは未決着。

Gemini CLI での実施を試みたが、無料枠クライアントが廃止されており失敗
（`IneligibleTierError: This client is no longer supported`）。
他モデルのCLI・APIキーが利用可能になり次第、対照群をもう1本作って決着させること。
