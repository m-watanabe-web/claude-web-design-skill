# 検証ログ：禁止リストは効くのか（2026-08-19）

## 目的
「禁止リストを渡すとAI感が減る」という前提が、現行モデルで成立するかを確かめる。
成立しなければスキル化そのものを中止する、という条件で実施した。

## 方法
- **条件A（対照）**：ブリーフのみを渡す。禁止リスト・design-spec は渡さない。
  **この会話の文脈を持たない白紙のサブエージェント**が生成（生成者の汚染を避けるため）。
- **条件B（実験）**：同じブリーフ ＋ `forbid.md` ＋ `design-spec.yaml`。
- **題材2種**：(a) 日本茶ブランドLP（中立な架空案件）、(c) エンジニアのポートフォリオLP。
- **評価**：主観を排し、HTML/CSSへの機械測定（`measure.py`）。
- **事前登録した合否基準**：Bで違反が残れば中止／Aが既にクリーンなら前提崩壊とみなす。

## 結果

| 指標 | A-a | B-a | A-c | B-c | 判定 |
|---|---|---|---|---|---|
| 紫系の色 | 0 | 0 | 0 | 0 | 差なし |
| 絵文字 | 0 | 0 | 0 | 0 | 差なし |
| 装飾グラデーション | 1 | 0 | 0 | 0 | ほぼ差なし |
| 色相数 | 5 | 3 | 2 | 2 | 片方のみ |
| border-radius | 6 | 0 | 6 | 0 | **差あり** |
| 均一カード羅列 | 3 | 0 | 2 | 0 | **差あり** |
| アニメーション | 0 | 0 | 3 | 0 | **差あり** |
| サイズ | 44KB | 6KB | 21KB | 5KB | **差あり** |

対照群が実際に選んだ配色：(a) 緑→金→橙のアースカラー、(c) 紺＋青。**紫は出現せず**。

## 結論
**部分的に前提崩壊。** 出典で最も強調されていた「紫グラデ」「絵文字」は、
禁止しない条件でも出なかった＝**何も禁止していなかった**。
一方、構造的な癖（角丸カードの均一グリッド、無意味アニメ、冗長さ）は明確に残る。
→ 禁止リストの内容を半分入れ替えた上で継続する、と判断。

## 測定器に混入したバグ（2件・修正済み）
1. 絵文字判定に矢印 `→`(U+2192) を含めており、「絵文字2件」は全て誤検出だった。
2. グラデーション抽出の正規表現が `)}` で終わる記述を取り逃し、
   `linear-gradient(90deg,#8FA97A,#C9A24B,#B4642F)` を見落としていた。
→ 括弧の対応を数える方式に変更。**初回の測定結果は両方とも誤りだった。**
チェックリストを作れば品質が担保される、という発想自体への反証。

## この検証の限界
- **各条件 n=1**。角丸6件のような大きい差は偶然で説明しにくいが、色相数の差は誤差の範囲。
- **対照群も同じモデル**（サブエージェントはセッションのモデルを継承）。
  検証できたのは「Opus 5の癖」であって「AI一般の癖」ではない。
- **実写真のレバーは検証不能**（オフラインで本物の画像を用意できず、両条件とも実素材0）。
- **Step 1・2 のプロセス論は未検証**（一発生成では差が出ない性質）。
- **ツール比較（Gemini等）は未実施**。

## 第2ラウンド：UX観点（同日）

見た目しか測っていなかったため、UX指標を追加して測り直した。

| 指標 | A-c（対照） | B-c（見た目リストのみ） | **B2-c（ux.md＋forbid.md）** |
| --- | --- | --- | --- |
| コントラスト違反（実測） | 0 | **4**（最悪 2.71:1） | **0**（最悪 6.15:1） |
| `:focus` | あり | **なし** | あり |
| `prefers-reduced-motion` | あり | **なし** | あり |
| `<main>` | あり | **なし** | あり |
| 見出し階層 | 正常 | **h1→h3 飛び** | 正常 |
| 空リンク | 0 | **1** | 0 |
| メディアクエリ | 9 | **1** | 2 |
| 角丸 | 6 | 0 | 0 |
| 均一カード | 2 | 0 | 0 |
| サイズ | 21KB | 5KB | 6KB |

**結論：見た目の禁止リスト単独では、対照群よりUXが悪化する。**
「角丸を使うな」「アニメを入れるな」「短くしろ」と縛った結果、フォーカス表示と reduced-motion が削られた。
対照群は指示なしでそれらを実装していた。
両方（`ux.md` ＋ `forbid.md`）を適用した B2-c で、**UX全項目クリア＋見た目クリアを両立**できた。

茶の題材でも同じ結果。B2-a（両方適用）で全項目クリア。

| 指標 | A-a（対照） | B-a（見た目のみ） | **B2-a（UX＋見た目）** |
| --- | --- | --- | --- |
| コントラスト違反（実測） | **64** | **15**（最悪 4.34:1） | **0**（最悪 6.76:1） |
| `:focus` / `<main>` / 見出し階層 | なし / なし / 飛びなし | **なし / なし / 飛びあり** | あり / あり / 正常 |
| 空リンク | 0 | **1** | 0 |
| 角丸 / 均一カード | 6 / 3 | 0 / 0 | 0 / 0 |

**どの条件でもコントラスト違反は出る**（対照群64件、見た目リストのみ15件）。
リストの有無に関わらず、提出前の実測は必須。

### 測定器のバグ（累計4件）
3. 静的解析のコントラスト判定が、入れ子の背景を追えず誤検出・見逃しの両方を起こした
   → Chrome headless の実レンダリングに切り替え（`contrast.py`）
4. Chrome は `color-mix()` を `color(srgb ...)` 形式で返すため、`rgba()` だけを見ていた解析器が
   **該当要素を黙って検査対象外にしていた**（B系が「違反0件」に見えていた）

**「違反0件」は、まず測定器を疑う。** 4件中2件が偽陰性だった。

## 成果物
`samples/` に5本のHTMLを保存（A=対照、B=見た目のみ、B2=UX＋見た目）。再現手順：
```
python3 references/measure.py  references/samples/*.html      # 静的（UX＋見た目）
python3 references/contrast.py references/samples/*.html      # コントラスト実測
```
