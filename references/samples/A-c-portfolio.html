01 — Strength

できること、続けてきたこと

Structure

バラバラの情報を、構造化する

形式の揃っていない記述や自由記入のテキストを、後工程が機械的に扱える形に整えます。件数が増えても同じ品質で通るように、処理の手順そのものを設計します。

Automate

人がやらなくていい作業を、外す

手作業の工程を洗い出し、自動化できる部分とレビューが要る部分を切り分けます。全部を機械に任せず、人が確認すべき一点を残すことで、精度と速度を両立させます。

Align

可視化して、判断を前に進める

処理の流れ・データの状態・詰まりどころを図と数字で示し、技術者以外にも同じ絵が見えるようにします。認識が揃えば、意思決定は止まりません。

02 — Selected Work

実績

Process Redesign

現状分析 / 自動化設計 / 実装 / 定着

手作業前提の業務を組み替え、120人日を80人日に

担当者ごとにやり方が違い、工数の内訳も見えていなかった業務を対象に、まず工程を分解して所要時間を数字で並べるところから始めました。削るべき工程が合意できたうえで自動化を組み、運用に載せています。

  • 工数：120人日 → 80人日
  • 対象人数：240名
  • 対象データ：約3.5万件
  • 効果を工程別に可視化し、優先順位を関係者と合意したうえで着手

Medical Registry

データ構造化 / LLM活用 / パイプライン構築

研究データ基盤を、使える形に整える

表記ゆれや自由記述を含む記録を、分析・集計に耐える構造へ変換する仕組みを担当しました。ルールで確実に処理できる部分と、判断が要る部分を切り分け、後者にLLMを充てる構成にしています。

  • 入力の揺れを吸収する正規化処理と、変換結果の検証工程をセットで設計
  • LLMの出力をそのまま採用せず、確認しやすい形で人のレビューに回す流れを用意
  • 扱う情報の性質上、取り扱い範囲と保管方法を先に定義してから実装に着手

Facility Industry

業務委託 / 要件定義 / 設計

製造業の案件で、要件定義から設計まで

業務委託として、現場の運用を聞き取りながら要件を固め、設計に落とすところまでを担当しました。用語も前提も社内と異なる領域だったため、認識合わせの図を早い段階で出し、認識のずれを実装前に潰しています。

  • 現場ヒアリングをもとに、やりたいことと決まっていないことを分けて整理
  • 業務フローと想定データの流れを図で共有し、仕様の合意を先行させる進め方
  • 非エンジニアの担当者が読んで判断できる粒度でドキュメントを作成

03 — How I Work

進め方

  1. 01

    現状を数字で置く

    体感ではなく、工程ごとの件数と時間を並べます。ここで「どこが重いか」が全員に見えると、以降の判断が速くなります。

  2. 02

    図にして、認識を揃える

    データの流れと処理の分岐を1枚にまとめ、技術者以外にも読める状態で共有します。手戻りの大半は、この段階で防げます。

  3. 03

    小さく作って、確かめる

    いきなり全体を組まず、効果が大きい工程から動くものを出して検証します。想定と違えば、その場で設計に戻します。

  4. 04

    人の確認を残して、運用に載せる

    自動化した処理にも、結果を確認できる出口を用意します。担当者が中身を追える状態にして初めて、仕組みは引き継がれます。
